# Proposal: Hooklet Developer Onboarding Overhaul

**Prepared for:** Hooklet, attn. Maya Trent (DevRel Lead)
**Prepared by:** Release Mode LLC
**Date:** 2026-05-19
**Valid until:** 2026-06-09

## The problem

Your quickstart takes a new developer 11 steps and two API keys to deliver their first webhook. Your own forum's most-viewed thread is a setup complaint, and "redesigned onboarding" has sat in the exploring column of your roadmap for two quarters. Meanwhile the number your team is accountable for — developer signups converting to active integrations — is flat.

You don't have a documentation problem; you have an unmeasured funnel between signup and first delivered webhook, and nobody owns the minutes it takes.

## Proposed engagement

A four-week engagement that measures your actual time-to-first-webhook, removes the worst friction, and leaves you with the instrumentation to keep it from regressing.

## Deliverables

| Deliverable | Description | Acceptance looks like |
|---|---|---|
| DX audit report | Timed cold walkthrough of the quickstart, severity-ranked findings | Report delivered with TTFV baseline and per-step timings |
| Quickstart rewrite | New quickstart implementing the audit's blocker/major fixes | A new developer reaches first delivered webhook in under 5 minutes, verified on camera |
| Metrics one-pager | Activation definition + the 5 funnel events to instrument | Engineering confirms each event is implementable from the spec |

## Out of scope

- SDK or API changes (findings will be filed as issues, not fixed)
- Docs-site redesign, information architecture, or tooling migration
- Ongoing content production after the engagement ends

- **Week 4:** metrics one-pager, handoff call
